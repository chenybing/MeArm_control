## 二、任务一：机械臂基本功能

### 2.1 基础控制（各关节独立移动 + 摇杆实时操控）

**代码模块**：`joystickAll()` / `joyTarget()` / `smoothJoint()`

`loop()` 每轮读 4 个摇杆轴（`analogRead` 返回 0~1023），做三件事：

1. **死区判断**：读数偏离中位 512 不足 `JOY_DEADZONE`(40) 就视为"没动"。摇杆是电位器，回中时读数会抖动，不去死区舵机会不停哆嗦。
2. **角度换算**：把 0~1023 按比例映射到 0~180°。
3. **平滑逼近**：`cur += (target - cur) × 0.25`，每轮只走差值的 25%，动作柔和，不会瞬间跳变。

**各关节独立移动**通过把每个关节的角度变量解耦实现：`curBase / curShoulder / curElbow / curGripper` 各自独立更新，互不影响，因此任意单个关节可以单独运动，也可以同时运动。

### 2.2 固定指令通信（O / S / H / L）

**代码模块**：`dispatch()` 的单字符分支、`cmdGripper()`、`speedLevel`

- `O` → 夹爪转到 `GRIP_OPEN`(20°)；`S` → 转到 `GRIP_CLOSE`(110°)。
- `H` / `L` → 调整**速度档** 1~5。舵机库本身没有调速接口，实现方式是"一步 1°、每步延时"：

  ```
  stepDelay() = 44 − speedLevel × 7   (ms)
  档1 = 37ms/步（最慢） … 档5 = 9ms/步（最快）
  ```

  与早期版本不同，本程序里 `H/L` 调整的是**全局速度**，所有动作（夹取、绘制、回放）都立即跟着变，符合"提升机械臂**整体**运行速度"的要求。

### 2.3 多舵机协同控制（x,y,z）

**代码模块**：`cmdMultiServo()` / `numAfter()` / `moveJoints()`

- **解析**：`numAfter(str, 'x')` 找到字母 `x` 的位置，跳过非数字字符后 `atoi` 取数。因为按字母定位而不是按位置切分，所以 `x/y/z` 的**书写顺序可以任意**（` y90,x10,z20` 也能正确解析），比按固定下标 `substring` 更健壮。
- **同步**：`moveJoints()` 的一个循环里，三个（实为四个）舵机各走 1° 后**连续** `write`，最后统一 `delay`。因为 PWM 在同一轮里连续输出、延时一致，视觉上就是同步起步、同步到位。

### 2.4 版本管理

本仓库即考核用的 GitHub 仓库，按功能点分阶段提交，开发过程中使用过分支（见提交记录）。

## 三、任务二：A / B / C 夹取与放置

**代码模块**：`pickAndPlace()` / `cyclePick()`、常量 `PICK_U/V[]`、`PLACE_U/V[]`

### 3.1 点位定义与"三个明显不同的位置"

用桌面坐标定义取物位与放置位，**每个物体有自己独立的放置位**：

| 物体 | 取物位 (u, v) | 放置位 (u, v) | 位移 Δ(u, v) |
|---|---|---|---|
| A | (−5.0, 8.5) | (−2.5, 12.5) | (+2.5, +4.0) |
| B | ( 0.0, 9.0) | (+2.5, 13.0) | (+2.5, +4.0) |
| C | (+5.0, 8.5) | (−5.0, 12.0) | (−10.0, +3.5) |

- 三个放置位**互不相同**（u 分别为 −2.5 / +2.5 / −5.0，v 分别为 12.5 / 13.0 / 12.0）；
- 每个物体的取物位与放置位在 **u 和 v 两个方向上都有明显位移**，满足考核要求。

### 3.2 动作序列（6 步）

取放一个物体固定走这条路径，这是工业机器人取放的标准安全路径——
**先升到安全高度 → 水平移动 → 再下降**，避免拖着物体从别的物体上方划过：

```
① 抬到安全高度 CARRY_H      ② 张开夹爪
③ 到取物位上方 → ④ 下降到 GRIP_H 对准物体
⑤ 合爪抓取（停 300ms 夹稳）  ⑥ 抬起
⑦ 转到放置位上方 → ⑧ 下降    ⑨ 开爪放下（停 300ms 落稳）
⑩ 抬起离开
```

### 3.3 指令响应

上位机发送 `A` / `B` / `C` 分别触发对应物体的取放（大小写均可）。
`RUN` 把三次连做。任务三的按键 1 复用同一套 `pickAndPlace()`，只是用 `cycleIdx` 记录循环到了哪个物体。

## 四、任务三：按键遥控板联动

**代码模块**：`toggleRecord()` / `recordStep()` / `playRecord()` / `cyclePick()` / `goHome()`，
发送端见 `remote_serial/remote_serial.ino`

### 4.1 串口协议

遥控板捕获 4 个按键后，通过串口（9600）发送**单字符 + 换行**：

```
按键1 → "1\n"   按键2 → "2\n"   按键3 → "3\n"   按键4 → "4\n"
```

接收端为**行解析**：逐字符攒进缓冲区，遇到 `\n` / `\r` 或者**字符间隔超过 40ms**就认为一条指令结束。
这样无论遥控板是否补换行符都能正确分帧——这是现场最容易翻车的地方，所以做了兼容。

机械臂每完成一次状态切换会回传一行 `STAT:xxx`（`IDLE` / `MANUAL` / `REC` / `PLAY` / `TEACH` / `DRAWING` / `PAUSED`），
遥控板可直接解析显示到 OLED 上。

**接线与注意事项**见 `remote_serial.ino` 头部注释（核心：两块板必须共地；用硬件串口 D0/D1 时演示任务三需拔掉机械臂 USB 线，否则板载 CH340 会与遥控板 TX 抢总线；如需同时插 USB，把 `mearm_main.ino` 顶部的 `REMOTE_SOFT_SERIAL` 改成 1，改用软串口 D12/D13）。

### 4.2 按键 1：循环夹取（10%）

维护一个循环计数 `cycleIdx ∈ {0,1,2}`，每按一次执行 `pickAndPlace(cycleIdx)` 然后 `cycleIdx = (cycleIdx+1) % 3`。
第一次按夹 A，第二次夹 B，第三次夹 C，之后回到 A，无限循环。

### 4.3 按键 2：录制

**数据结构**：

```cpp
const uint16_t REC_MAX = 200;   // 最多 200 帧
const uint16_t REC_MS  = 60;    // 每帧 60ms  → 最长 12 秒（要求 >10 秒）
uint8_t recBuf[REC_MAX][4];     // 每帧存 4 个舵机角度，各占 1 字节 = 800 字节
```

**为什么这样设计**：

- 舵机角度是 0~180 的整数，正好塞进 `uint8_t`，一帧只占 4 字节。Uno 只有 2KB SRAM，用 `int` 会把内存占满（`200×4×2 = 1600` 字节），而 800 字节可以留出足够余量给栈和串口缓冲。
- 60ms 采样周期 → 12 秒容量，满足">10 秒"的要求并留有余量；16.7Hz 的采样率对摇杆这种慢速操作足够平滑。

**流程**：第一次按下 → `mode = MODE_REC`，每轮 `joystickAll()` 驱动四关节，同时每 60ms 把当前角度存入 `recBuf`；
第二次按下 → 结束录制，打印时长；**若不足 10 秒会提示"建议重新录制"**。
如果录满 200 帧自动停止并保留已录数据（不会丢帧），同时提示。

### 4.4 按键 3：回放

按 `REC_MS` 的原始时序，逐帧把 `recBuf` 里的角度直接写回四个舵机，完整复现录制时的人工操作。
回放过程中同样响应"取消"（`CANCEL` 指令或 D10 按键），不会卡死在长动作里。

### 4.5 按键 4：回中

`goHome()` 四轴同步回到 `(90,90,90,90)` 初始姿态。

## 五、任务五：轨迹绘制与画图（35%，难度分累计）

### 5.1 运动学：末端位置 → 关节角度

**代码模块**：`tableToJoints()`（逆解）、`jointsToTable()`（正解）

机械臂大臂 + 小臂构成一个**二连杆机构**。给定桌面坐标 `(u, v, h)`：

```
① 底座角   θ = atan2(u, v)  → 把机械臂转到目标所在的竖直平面内
   底座舵机角 = BASE_ANG ± θ        （BASE_ANG = 90° 为正前方）

② 臂展半径 r = √(u² + v²)，笔尖相对肩关节轴的高度 z = h − H_SHOULDER

③ 二连杆逆解（余弦定理 + atan2）：
   d  = √(r² + z²)                                  末端到肩轴距离
   e  = ±acos((d² − L1² − L2²) / (2·L1·L2))          肘角（取符号由解支决定）
   s  = atan2(z, r) − atan2(L2·sin e, L1 + L2·cos e) 大臂角

④ 连杆角 → 舵机角：舵机角 = TRIM ± 连杆角   （由标定开关决定符号）
```

**关于解支（`ELBOW_SIGN`）**：`acos` 给出两个对称解。桌面画图时笔尖在肩关节**下方**（`z = −H_SHOULDER`），
这里取 `ELBOW_SIGN = −1`（"小臂下垂"解），此时大臂略向上、小臂向前下方伸出，
肘关节不会撞到桌面；若取正解，大臂会插入桌面，物理上不可实现。

**正解**（`jointsToTable`）是上式的严格逆运算，用于示教时把当前姿态换算成笔尖坐标、以及标定调试。

### 5.2 子任务 1：直线绘制（难度 6）

**代码模块**：`drawLineDemo()`

线性插值：`t` 从 0 走到 1，`u = u1 + (u2−u1)·t`，离散成 40 段逐点移动。
抬笔 → 移到起点上方 → 落笔 → 逐点画到终点。插值点足够密，画出来就是一条连续直线。

### 5.3 子任务 2：基础图形（难度 10）

**代码模块**：`drawFigure()`

按考核要求在 **N / 三角形 / Z / V** 中任选（本题四种全部实现，现场可任选一种演示，避免与小组成员重复）：

| 图形 | 顶点序列 |
|---|---|
| N | 左下 → 左上 → 右下 → 右上（左竖 + 斜线 + 右竖） |
| 三角形 | 顶点 → 左下 → 右下 → 顶点（等边，高 = 边长×0.866，一笔闭合） |
| Z | 左上 → 右上 → 左下 → 右下（上横 + 斜线 + 下横） |
| V | 左上 → 中点下方 → 右上 |

每个图形先算好顶点坐标，再对**每一条边**做线性插值（每边 25 个点），保证线段笔直、拐角处不会"抄近路"。

### 5.4 子任务 3：绘图过程控制（难度 24）

**代码模块**：`stepGate()` / `moveJoints()`，按键 D2 / D3 / D10

这是本任务的关键设计：**所有运动都被拆成一"步"一步**（每步各关节走 1°），
而 `moveJoints()` 在**每一步之后**都调用一次 `stepGate()` 检查控制请求：

```cpp
bool stepGate() {
  scanButtons();            // 读取 暂停 / 继续 / 取消 三个按键
  handleMotionButtons();
  pollSerial(true);         // 同时受理串口的 PAUSE / RESUME / CANCEL
  while (stPause && !stAbort) {   // 暂停：原地保持，舵机不动
    scanButtons(); handleMotionButtons(); pollSerial(true);
    delay(5);
  }
  return stAbort;           // 被取消 → 调用方立即中止当前动作
}
```

因此三个功能的语义严格符合要求：

- **暂停**：置 `stPause = true`，运动循环停在原地，**舵机保持当前角度不动，任务状态完整保留**（当前画到第几个点、第几段都在局部变量里，不受影响）。
- **继续**：清 `stPause`，循环从**当前角度**继续往原目标走，无缝接续，不会回到起点重画。
- **取消**：置 `stAbort = true`，逐层 `return` 中止整条轨迹；`endDrawTask()` 会清除标志并驱动机械臂**返回待机位**，回到待机状态。

按键与串口指令**都可以**触发（现场用按键，也可以从串口监视器发指令救急）。

### 5.5 子任务 4：五点示教 + 折线轨迹规划（难度 30）

**代码模块**：`enterTeach()` / `teachStep()` / `recordTeachPoint()` / `drawByTeach(false)`

**（1）示教点记录**

- `TEACH` 进入示教模式，摇杆 1 控制笔尖在桌面平面移动：X 轴 → `u`（左右），Y 轴 → `v`（前后）。
- 移动用**浮点累加器** `tgU / tgV` 保存目标位置，而不是每次从当前姿态重新推算。
  原因：舵机角是整数（1° 在 8cm 臂展上约 1.4mm），若每轮重新取整，小幅推杆的位移会被"吃掉"，笔尖推不动；
  浮点累加可以让微小增量**累积**起来，越过 1° 的分辨率后笔尖才动一格——手感是"一格一格"的，但一定能到。
- 累加器会钳制在可达半径 `[R_MIN, R_MAX]` 内，避免一直往够不着的方向累加。
- 笔尖停在 `TEACH_H`（离纸面 0.3cm）便于瞄准，不会拖坏纸面。
- 按 **D11** 或发送 `SET` 记录当前点：用**正解**把当前关节角换算成精确的 `(u, v)` 存入 `teachU[] / teachV[]`，并回显"已记录示教点 n/5"。记录的是实际到达的位置，因此后续复现一定能到达。
- 5 个点记录完毕后可用 `CLR` 清空重录，`DRAW` / `CURVE` 开始自动绘制。

> 现场答辩时考官临时指定五个点，只需 `TEACH` → 摇杆找点 → `SET` ×5 → `DRAW`/`CURVE`，
> **不需要重新编译或烧录**，符合考核要求。

**（2）自动绘制流程**

严格按"先返回待机位置，再移动至第一个目标点，之后依次连接"的要求：

```
回待机位 (0, 8, h=4)  →  抬笔移动到点 1 正上方  →  落笔到点 1
  →  点 1 → 点 2  →  点 2 → 点 3  →  点 3 → 点 4  →  点 4 → 点 5
  →  抬笔回到待机位
```

每段用 25 个插值点细分（`t` 从 1/25 到 1），保证**实际走出来的轨迹是直线**而不是"两点之间直接甩过去"。
绘制全程受 5.4 的暂停 / 继续 / 取消控制。

`DEMO` 指令用内置的五个点快速演示，方便调试和录制视频。

### 5.6 子任务 5：五点示教 + 平滑曲线轨迹规划（难度 30）

**代码模块**：`drawByTeach(true)` / `catmullRom()`

示教与记录方式与子任务 4 完全相同，区别在轨迹生成：使用 **Catmull-Rom 样条**。

**为什么用 Catmull-Rom**：两点连直线在折点处方向突变，机械臂走到折点相当于"急转弯"，既难看又容易抖动。
Catmull-Rom 的好处是**曲线严格经过每一个给定的点**（不像 B 样条只逼近），这对"示教点必须过点有效"的评分要求是刚需。

**原理**：画第 `i` 段（连接 `P[i] → P[i+1]`）时，不只用自己的两个端点，还"偷看"前后邻居 `P[i-1]` 和 `P[i+2]`，用这四个点决定这一小段的走向：

```
u(t) = 0.5 × ( 2·P1
             + (−P0 + P2)·t
             + (2·P0 − 5·P1 + 4·P2 − P3)·t²
             + (−P0 + 3·P1 − 3·P2 + P3)·t³ )
```

- 起点处切线方向 = `P2 − P0`，终点处切线方向 = `P3 − P1`；
- 相邻两段共享同一个算法，段与段之间切线连续变化 → 整条曲线处处平滑（数学上称 **C1 连续**）；
- **端点处理**：第一段缺 `P[-1]`、最后一段缺 `P[n]`，直接"复制"端点（`P[-1] = P[0]`，`P[n] = P[n-1]`），曲线从第一个点平滑滑入、平滑滑出；
- **过点验证**：代入 `t=0` 得 `u = P1`，代入 `t=1` 各项合并后得 `u = P2`，因此每个给定点都是曲线上的点——**这是数学保证，不是近似**。

每段采样 30 个点。自动绘制流程与子任务 4 一致（回待机 → 抬笔到点 1 → 落笔 → 沿曲线过五点 → 抬笔回待机），同样支持暂停 / 继续 / 取消。

### 5.7 速度控制

速度由**全局速度档**统一控制，`H` / `L` 指令或串口调整：

```
每步延时 stepDelay() = 44 − speedLevel × 7  (ms)     档 1~5 → 37 / 30 / 23 / 16 / 9 ms
```

之所以用"每步 1° + 延时"而不是直接 `write(目标角)`：舵机一旦收到差距很大的目标角会全速冲过去，速度不可控、启停冲击大。
**拆成 1° 的小步 + 固定延时**，等价于给舵机制造了一个软件速度环，动作平稳可控，也才可能实现"暂停后原地停住、继续后接续"。

另外插值点数（直线 40 点、图形每边 25 点、折线每段 25 点、曲线每段 30 点）也影响绘制速度与平滑度，
点数越密越平滑但越慢，可在代码顶部的参数区调整。

## 六、异常处理与鲁棒性

| 异常情况 | 处理方法 | 位置 |
|---|---|---|
| 目标点超出机械臂可达范围 | 沿原方向**钳制到可达球面**（`d` 缩放到 `L1+L2` 的 99.5%），机械臂朝目标方向走到极限并打印 `WARN`，**而不是原地不动或乱走** | `tableToJoints()` |
| 逆解失败导致使用未初始化变量 | 早期版本 `targetToAngles()` 不可达时直接 `return`，调用方会拿到栈垃圾、机械臂乱甩。已改为**返回 `bool` + 输出参数赋哨兵值**，调用方检查返回值后跳过该点 | `mearm_drawing.ino` / `mearm_curve_smooth.ino` |
| 目标半径/底座角超出可达范围 | `r` 钳制到 `[R_MIN, R_MAX]`，底座角钳制在 `BASE_ANG ± BASE_SWEEP` | `tableToJoints()` |
| 示教点不足 | `DRAW` / `CURVE` 前检查 `teachCount ≥ 2`，否则提示"示教点不足 2 个"并拒绝执行 | `drawByTeach()` |
| 示教点超过 5 个 | 拒绝记录并提示"如需重录请发送 CLR 清空"，不会数组越界 | `recordTeachPoint()` |
| 回放时还没有录制数据 | 提示"还没有录制数据，请先按 2 录制"并拒绝执行 | `playRecord()` |
| 录制时长不足 10 秒 | 结束录制时打印 `WARN 录制时长不足 10 秒，建议重新录制` | `toggleRecord()` |
| 录制缓冲写满 | **自动结束录制并保留已录数据**（不丢帧），打印提示 | `recordStep()` |
| 串口缓存溢出 | 单条指令超过 48 字节时丢弃并提示 `ERR: 指令过长`，不会越界 | `pollOne()` |
| 串口收不到换行符 | 字符间隔超过 40ms 自动分帧，兼容不带换行的遥控板 | `pollOne()` |
| 动作执行中途收到新指令 | 只受理 `PAUSE` / `RESUME` / `CANCEL` / `STATUS`，其余回 `BUSY`，避免递归触发动作导致状态错乱 | `dispatchInMotion()` |
| 按键抖动 / 连击 | 180ms 时间锁消抖，一次按下只触发一次 | `scanButtons()` |
| 上电瞬间舵机乱甩 | `setup()` 里先统一写 90° 中间安全姿态 | `setup()` |
| 取消绘图后标志未清除 | `endDrawTask()` 先清 `stAbort` 再回待机位，否则回程本身也会被立刻取消 | `endDrawTask()` |
| 内存不足 | 不使用 `String`（避免碎片），串口用固定 `char[]` 缓冲，录制用 `uint8_t` 压缩存储；实测 Flash 14.1KB/32KB、静态 SRAM 1.0KB/2KB | 全局 |
| 函数名与标准库冲突 | 状态上报函数由 `stat()` 改名为 `printStat()`，避免与 POSIX `stat()` 撞名 | `printStat()` |

## 七、标定步骤（画图前必做）

程序里的几何参数必须按实物标定，否则画出来是歪的：

1. **量尺寸**：`ARM_L1`（肩关节轴 → 肘关节轴）、`ARM_L2`（肘关节轴 → **笔尖**，不是腕中心）、
   `H_SHOULDER`（肩关节轴离桌面的高度）。
2. **校方向**：进入 `M` 模式，用摇杆把大臂抬到"水平前伸"，执行 `CAL` 看打印的坐标是否合理。
   - 方向反了 → 翻开对应的 `SHOULDER_INVERT` / `ELBOW_INVERT` / `BASE_INVERT`；
   - 整体偏一个固定角度 → 调 `SHOULDER_TRIM` / `ELBOW_TRIM`；
   - 直接用 `JOG 大臂角 肘角` 给连杆角（0 = 水平前伸，肘角 0 = 完全伸直）可以逐度试。
3. **校落点**：把笔尖手动移到桌面某个已知位置，执行 `CAL` 读出程序认为的 `(u, v)`，
   与卷尺量的实际值对比，微调 `H_SHOULDER` 与 `ARM_L2`。
