## 一、总览

### 1.1 程序组成

整个考核的功能整合在**一份工程** `mearm_main/` 里，并按任务拆成六个 `.ino` 文件。

> Arduino 编译一个 sketch 目录时，会把目录下所有 `.ino` **自动合并成一个编译单元**，
> 顺序为「主文件（与目录同名）排在最前，其余按字母序」。所以拆成多文件后，
> 它仍然是**一份可直接编译、烧录、复现视频效果的工程**，不需要任何额外配置。

| 文件 | 作用 |
|---|---|
| `mearm_main/mearm_main.ino` | **主文件**：公共常量与全局状态、`setup()`/`loop()`、串口接收与分帧、指令派发 |
| `mearm_main/kinematics.ino` | **公共模块**：按键扫描、`writeServos()` 安全行程限位、运动基元、正逆运动学、标定工具 |
| `mearm_main/task1_basic.ino` | **任务一**：摇杆操控、固定指令 `O`/`S`/`H`/`L`、多舵机协同 `x,y,z` |
| `mearm_main/task2_pick_place.ino` | **任务二**：A/B/C 取放点位与六步取放路径 |
| `mearm_main/task3_keyboard.ino` | **任务三**：按键1 循环夹取、按键2 录制、按键3 回放、按键4 回中 |
| `mearm_main/task5_drawing.ino` | **任务五**：绘图引擎、五点示教、折线与 Catmull-Rom 平滑曲线 |
| `remote_serial/remote_serial.ino` | **串口通信程序**（电路组按键遥控板的发送端，任务三配套） |

各关节的安全行程由逐度扫描实测得到，不属于任务代码。

> 注意：拼接顺序带来的两条约束，改动代码时必须遵守：
> 1. **跨文件使用的全局变量只能定义在 `mearm_main.ino`**（它排在最前）；各任务专属的状态变量放在各自文件里。
> 2. **跨文件的函数原型不允许出现自定义结构体**——Arduino 会把自动生成的函数原型插到合并文件开头，一旦原型里出现自定义结构体，就可能落在结构体定义之前导致编译失败。

## 二、任务一：机械臂基本功能

### 2.1 基础控制（各关节独立移动 + 摇杆实时操控）

**代码模块**：`joystickAll()` / `joyTarget()` / `smoothJoint()`

`loop()` 每轮读 4 个摇杆轴（`analogRead` 返回 0~1023），做三件事：

1. **死区判断**：读数偏离该轴**自己的中位**不足 `JOY_DEADZONE`(40) 就视为"没动"。摇杆是电位器，回中时读数会抖动，不去死区舵机会不停哆嗦。
   注意：四个轴的中位**各不相同**（本机实测 `JOY_CENTER[4]` = 529 / 512 / 529 / 509，用 `JOY` 指令现场读）。
   早期版本四个轴共用 512，会让死区一边宽一边窄 —— 表现是"往一个方向轻轻一推就动、
   往另一个方向要推很多才动"。现在按各轴自己的中位归零，两侧半量程分别缩放。
2. **角度换算**：把 0~1023 按比例映射到 0~180°。
3. **平滑逼近**：每轮只走差值的一个比例，动作柔和，不会瞬间跳变。比例由 `joyFollowRate()`
   给出，**随 `H`/`L` 速度档变化**（档 1 = 0.020 最柔 / 档 3 = 0.055 默认 / 档 5 = 0.110 最快），
   这样"整体运行速度"对摇杆操控同样生效。

   注意：另有一道**硬上限**（`JOY_STEP_BASE` / `JOY_STEP_SHOULDER` / `JOY_STEP_ELBOW` /
   `JOY_STEP_GRIPPER`，**每个轴可以不一样**）：每轮最多走这么多度。
   没有它的话，杆推到底时误差是 90°，按比例一算一步就是 20 多度，而一轮只有 10ms
   ≈ 2000°/秒，机械臂像被抽了一鞭子。

   **小臂（肘）的上限特意给得比别的轴大**（3.0°，约 300°/秒，别的轴 1.3°）。
   原因：位置舵机的输出力矩跟"指令减当前"的差值有关 —— 差值太小，舵机反而使不上劲，
   小臂（负载最重、要抬着整个前臂 + 手 + 笔）就抬不起来。这是上机实测得出的。

   位置用**小数**累积（`joyPosBase` / `joyPosShoulder` / `joyPosElbow` / `joyPosGrip`
   四个 `float`），不是直接在整数角度上走。早期版本用整数，差值不足 1° 时会被取整成 0、
   只能强制走 1°，结果是"不管推多轻一律 100°/秒"；改用小数累积之后，轻轻推才真的能慢慢走。

   若现场发现**推杆方向与机械臂实际方向相反**，翻 `mearm_main.ino` 顶部的
   `JOY_INV_J1X / JOY_INV_J1Y / JOY_INV_J2X / JOY_INV_J2Y` 四个开关即可（示教模式共用同一组）。
   注意：这与第 7 节的 `SHOULDER_INVERT / ELBOW_INVERT / BASE_INVERT` 是两回事：后者是**几何正
   方向**的标定开关，翻了会让逆解和绘图整体镜像，不能拿来调摇杆手感。

**各关节独立移动**通过把每个关节的角度变量解耦实现：`curBase / curShoulder / curElbow / curGripper` 各自独立更新，互不影响，因此任意单个关节可以单独运动，也可以同时运动。

### 2.2 固定指令通信（O / S / H / L）

**代码模块**：`dispatch()` 的单字符分支、`cmdGripper()`、`speedLevel`

- `O` → 夹爪转到 `GRIP_OPEN`(**127**)；`S` → 转到 `GRIP_CLOSE`(**60**)。
  注意：这两个值必须落在**实测安全行程** `GR_MIN~GR_MAX`(**60~127**) 之内。
  （**2026-10-13 晚**机械臂 + 夹爪都微调后重测定的值；旧的 167 / 66 已作废。）
  夹爪数字的口径是**逻辑角：大 = 张开、小 = 闭合**。硬件其实是反的（舵机原始角
  小 = 开、大 = 闭），所以代码在**唯一输出口 `writeServos()` 里做了一次镜像**
  （`svGripper.write(GR_RAW_SUM - curGripper)`，`GR_RAW_SUM = 220`）。
  全程序其余地方一律用逻辑角，因此 `O`/`S` 与题目要求的"O = 张开"一致。
  与舵机原始角对照时换算：**逻辑角 = 220 − 原始角**。
  旧版本写过 20°/110°、122°/168°、12°/142°，都是旧爪按旧行程定的，已作废。
- `H` / `L` → 调整**速度档** 1~5。舵机库本身没有调速接口，实现方式是"一步 1°、每步延时"：

  ```
  STEP_DELAY_TAB[5] = { 100, 50, 28, 16, 9 }   (ms/步)
  档1 = 100ms/步（最慢，≈10°/秒） … 档5 = 9ms/步（最快）
  ```

  与早期版本不同，本程序里 `H/L` 调整的是**全局速度**，下列四类动作全部立即跟着变，
  符合"提升机械臂**整体**运行速度"的要求：

  | 动作 | 受什么控制 |
  |---|---|
  | 指令类运动（`A/B/C`、`O/S`、`x,y,z`、绘图、回中） | `stepDelay()` |
  | 摇杆实时操控（任务一 `M` 模式） | `joyFollowRate()` |
  | 录制回放（任务三 `3`） | `playbackDelay()` |
  | 绘图 / 示教过程中的暂停、继续 | 不受影响，始终即时响应 |

  回放以**档 3 为 1.0 倍**：不动 `H/L` 时严格按录制时的 60ms/帧逐帧重现，保证"完整复现"。

### 2.3 多舵机协同控制（x,y,z）

**代码模块**：`cmdMultiServo()` / `numAfter()` / `moveJoints()`

- **解析**：`numAfter(str, 'x')` 找到字母 `x` 的位置，跳过非数字字符后 `atoi` 取数。因为按字母定位而不是按位置切分，所以 `x/y/z` 的**书写顺序可以任意**（` y90,x10,z20` 也能正确解析），比按固定下标 `substring` 更健壮。
- **同步**：`moveJoints()` 的一个循环里，三个（实为四个）舵机各走 1° 后**连续** `write`，最后统一 `delay`。因为 PWM 在同一轮里连续输出、延时一致，视觉上就是同步起步、同步到位。

## 三、任务二：A / B / C 夹取与放置

**代码模块**：`pickAndPlace()` / `cyclePick()`、常量 `PICK_U/V[]`、`PLACE_U/V[]`

> 实测敲 `A` 会解出 `S≈8 / E≈117`（大臂压平 + 小臂折到顶），手臂直接杵住。
> 下面的 §3.1~3.3 保留作**备用逆解方案**的说明，`PICK_U/V`、`GRIP_CLOSE_OBJ[]`
> **仍是未按新模型实标的值**，真要用必须先重标。

### 3.1 点位定义与"三个明显不同的位置"

用桌面坐标定义取物位与放置位，**每个物体有自己独立的放置位**：

| 物体 | 取物位 (u, v) | 放置位 (u, v) | 位移 Δ(u, v) |
|---|---|---|---|
| A | (−5.0, 8.5) | (−2.5, 12.5) | (+2.5, +4.0) |
| B | ( 0.0, 9.0) | (+2.5, 13.0) | (+2.5, +4.0) |
| C | (+5.0, 8.5) | (−5.0, 12.0) | (−10.0, +3.5) |

- 三个放置位**互不相同**（u 分别为 −2.5 / +2.5 / −5.0，v 分别为 12.5 / 13.0 / 12.0）；
- 每个物体的取物位与放置位在 **u 和 v 两个方向上都有明显位移**，满足考核要求。

### 3.2 动作序列（6 步）

取放一个物体固定走这条路径，这是工业机器人取放的标准安全路径——
**先升到安全高度 → 水平移动 → 再下降**，避免拖着物体从别的物体上方划过：

```
① 抬到安全高度 CARRY_H      ② 张开夹爪
③ 到取物位上方 → ④ 下降到 GRIP_H_OBJ[idx] 对准物体
⑤ 合爪抓取至 GRIP_CLOSE_OBJ[idx]（停 300ms 夹稳）  ⑥ 抬起
⑦ 转到放置位上方 → ⑧ 下降    ⑨ 开爪放下（停 300ms 落稳）
⑩ 抬起离开
```

### 3.3 每种物体独立的夹取参数

考核规定 A = 三枚叠放硬币、B = 笔、C = 自定义物，**三者厚度差别很大**，共用一个夹取角
必然出问题：偏张开的一侧（数字大）→ 夹爪压根没碰到物体，一抬就掉；偏闭合的一侧
（数字小）→ 夹爪咬到底还差一截，舵机顶着机械止点"卡卡"响。因此每个物体各有自己的
**夹取角**与**夹取高度**：

| 物体 | `GRIP_CLOSE_OBJ[]` 夹取角（逻辑角） | `GRIP_H_OBJ[]` 夹取高度 |
|---|---|---|
| A 硬币 | 65（最薄，夹到最紧） | 0.6 cm |
| B 笔 | 70（= `PEN_GRIP`，**实测**"正好夹住笔"） | 0.9 cm |
| C 自定义 | 85 | 0.8 cm |

注意：上表**仍未实测**（B 那格已对齐实测的 `PEN_GRIP`；A / C 是"次序对、不超限位"的占位值）。
必须现场逐个标定：手动把夹爪合到刚好夹住该物体，看 `CAL` 打印的 `G=`（打的就是逻辑角）填进来
（松了往**小**调、顶死了往**大**调）。夹取角必须落在 `GR_MIN~GR_MAX`(**60~127**) 之内。

### 3.4 指令响应

上位机发送 `A` / `B` / `C` 分别触发对应物体的取放（大小写均可）。
`RUN` 把三次连做。任务三的按键 1 复用同一套**示教点位**（`runPickPlace()` → `runTeach5()`），
只是用 `cycleIdx` 记录循环到了哪个物体。

## 四、任务三：按键遥控板联动

**代码模块**：`toggleRecord()` / `recordStep()` / `playRecord()` / `cyclePick()` / `goHome()`，
发送端见 `remote_serial/remote_serial.ino`

### 4.1 串口协议

遥控板捕获 4 个按键后，通过串口（9600）发送**单字符 + 换行**：

```
按键1 → "1\n"   按键2 → "2\n"   按键3 → "3\n"   按键4 → "4\n"
```

接收端为**行解析**：逐字符攒进缓冲区，遇到 `\n` / `\r` 或者**字符间隔超过 40ms**就认为一条指令结束。
这样无论遥控板是否补换行符都能正确分帧——这是现场最容易翻车的地方，所以做了兼容。

机械臂每完成一次状态切换会回传一行 `STAT:xxx`（`IDLE` / `MANUAL` / `REC` / `PLAY` / `TEACH` / `DRAWING` / `PAUSED`），
遥控板可直接解析显示到 OLED 上。

**接线与注意事项**见 `remote_serial.ino` 头部注释（核心：两块板必须共地；用硬件串口 D0/D1 时演示任务三需拔掉机械臂 USB 线，否则板载 CH340 会与遥控板 TX 抢总线；如需同时插 USB，把 `mearm_main.ino` 顶部的 `REMOTE_SOFT_SERIAL` 改成 1，改用软串口 D12/D13）。

### 4.2 按键 1：循环夹取（10%）

维护一个循环计数 `cycleIdx ∈ {0,1,2}`，每按一次执行 `pickAndPlace(cycleIdx)` 然后 `cycleIdx = (cycleIdx+1) % 3`。
第一次按夹 A，第二次夹 B，第三次夹 C，之后回到 A，无限循环。

### 4.3 按键 2：录制

**数据结构**：

```cpp
const uint16_t REC_MAX = 200;   // 最多 200 帧
const uint16_t REC_MS  = 60;    // 每帧 60ms  → 最长 12 秒（要求 >10 秒）
uint8_t recBuf[REC_MAX][4];     // 每帧存 4 个舵机角度，各占 1 字节 = 800 字节
```

**为什么这样设计**：

- 舵机角度是 0~180 的整数，正好塞进 `uint8_t`，一帧只占 4 字节。Uno 只有 2KB SRAM，用 `int` 会把内存占满（`200×4×2 = 1600` 字节），而 800 字节可以留出足够余量给栈和串口缓冲。
- 60ms 采样周期 → 12 秒容量，满足">10 秒"的要求并留有余量；16.7Hz 的采样率对摇杆这种慢速操作足够平滑。

**流程**：第一次按下 → `mode = MODE_REC`，每轮 `joystickAll()` 驱动四关节，同时每 60ms 把当前角度存入 `recBuf`；
第二次按下 → 结束录制，打印时长；**若不足 10 秒会提示"建议重新录制"**。
如果录满 200 帧自动停止并保留已录数据（不会丢帧），同时提示。

### 4.4 按键 3：回放

按 `REC_MS` 的原始时序，逐帧把 `recBuf` 里的角度直接写回四个舵机，完整复现录制时的人工操作。
回放过程中同样响应"取消"（`CANCEL` 指令或 D10 按键），不会卡死在长动作里。

### 4.5 按键 4：回中

`goHome()` 四轴同步回到 `(90,90,90,90)` 初始姿态。

## 五、任务五：轨迹绘制与画图（35%，难度分累计）

### 5.1 运动学：末端位置 → 关节角度

**代码模块**：`tableToJoints()`（逆解）、`jointsToTable()`（正解）

机械臂大臂 + 小臂构成一个**二连杆机构**。给定桌面坐标 `(u, v, h)`：

```
① 底座角   θ = atan2(u, v)  → 把机械臂转到目标所在的竖直平面内
   底座舵机角 = BASE_ANG ± θ        （BASE_ANG = 86 为正前方，2026-10-13 晚实测定）

② 先把结构偏移扣掉，换成"从肩关节轴出发的腕轴坐标"：
   r0 = √(u² + v²)                    笔尖到底座轴的水平距离
   r  = r0 − L3A − L3B                腕轴的水平半径（从肩轴算）
   z  = (h + PEN_DROP) − H_SHOULDER   腕轴相对肩轴的高度

③ 二连杆逆解（余弦定理 + atan2）：
   d  = √(r² + z²)                                  腕轴到肩轴的距离
   e  = ±acos((d² − L1² − L2²) / (2·L1·L2))          二连杆内角（取符号由解支决定）
   s  = atan2(z, r) − atan2(L2·sin e, L1 + L2·cos e) 大臂角 θ1

④ 连杆角 → 舵机角：
   大臂：S = SHOULDER_TRIM − θ1
   小臂：E = ELBOW_TRIM + (θ1 + e)      注意是【θ1 + e】，不是 e
```

> **小臂那一行为什么要加 `θ1`**（2026-10-10 实测定死，详见
> `docs/任务四_补充_平行四边形与末端偏移.md` 第 0 节）：
> 小臂不是"肘上装颗舵机直接拧"的，而是由**装在底座上**的舵机经
> **平行四边形连杆**推上去。平行四边形的性质决定了
> **小臂的绝对朝向由那根曲柄直接定死，与大臂转多少度无关**。
> 所以小臂舵机角对应的是**绝对角 `θ1 + e`**，不是**相对角 `e`**。
>
> 实测证据：大臂从 `S130` 转到 `S110`（转 20°）、小臂舵机不变，
> 【腕轴 − 肘轴】只变了 0.25cm（读数误差量级）；按相对角算应该变 **2.7cm**。
>
> 注意：连带两条：
> - `ELBOW_TRIM` 的含义现在是"小臂**水平**（绝对角 = 0）时的舵机角"，
>   值 **101**（2026-10-13 晚重测定；旧值 100）。
> - 改成绝对角后，"小臂永远在大臂下面"**不再自动成立**（旧写法里它是白送的）。
>   `tableToJoints()` 里加了 `ELBOW_OVER_ARM_MAX` 显式钳制，
>   防止逆解算出一个把肘顶到机械止点的姿态（堵转 = 发热 = 烧舵机）。

**关于解支（`ELBOW_SIGN`）**：`acos` 给出两个对称解。桌面画图时笔尖在肩关节**下方**（`z = −H_SHOULDER`），
这里取 `ELBOW_SIGN = −1`（"小臂下垂"解），此时大臂略向上、小臂向前下方伸出，
肘关节不会撞到桌面；若取正解，大臂会插入桌面，物理上不可实现。

**正解**（`jointsToTable`）是上式的严格逆运算，用于示教时把当前姿态换算成笔尖坐标、以及标定调试。

### 5.4 子任务 3：绘图过程控制（难度 24）

**代码模块**：`stepGate()` / `moveJoints()`，按键 D2 / D3 / D10

这是本任务的关键设计：**所有运动都被拆成一"步"一步**（每步各关节走 1°），
而 `moveJoints()` 在**每一步之后**都调用一次 `stepGate()` 检查控制请求：

```cpp
bool stepGate() {
  scanButtons();            // 读取 暂停 / 继续 / 取消 三个按键
  handleMotionButtons();
  pollSerial(true);         // 同时受理串口的 PAUSE / RESUME / CANCEL
  while (stPause && !stAbort) {   // 暂停：原地保持，舵机不动
    scanButtons(); handleMotionButtons(); pollSerial(true);
    delay(5);
  }
  return stAbort;           // 被取消 → 调用方立即中止当前动作
}
```

因此三个功能的语义严格符合要求：

- **暂停**：置 `stPause = true`，运动循环停在原地，**舵机保持当前角度不动，任务状态完整保留**（当前画到第几个点、第几段都在局部变量里，不受影响）。
- **继续**：清 `stPause`，循环从**当前角度**继续往原目标走，无缝接续，不会回到起点重画。
- **取消**：置 `stAbort = true`，逐层 `return` 中止整条轨迹；`endDrawTask()` 会清除标志并驱动机械臂**返回待机位**，回到待机状态。

按键与串口指令**都可以**触发（现场用按键，也可以从串口监视器发指令救急）。

### 5.5 子任务 4：五点示教 + 折线轨迹规划（难度 30）

**代码模块**：`enterTeach()` / `teachStep()` / `recordTeachPoint()` / `drawByTeach(false)`

**（1）示教点记录**

- `TEACH` 进入示教模式，摇杆 1 控制笔尖在桌面平面移动：X 轴 → `u`（左右），Y 轴 → `v`（前后）。
- 移动用**浮点累加器** `tgU / tgV` 保存目标位置，而不是每次从当前姿态重新推算。
  原因：舵机角是整数（1° 在 8cm 臂展上约 1.4mm），若每轮重新取整，小幅推杆的位移会被"吃掉"，笔尖推不动；
  浮点累加可以让微小增量**累积**起来，越过 1° 的分辨率后笔尖才动一格——手感是"一格一格"的，但一定能到。
- 累加器会钳制在可达半径 `[R_MIN, R_MAX]` 内，避免一直往够不着的方向累加。
- 笔尖停在 `TEACH_H`（离纸面 0.3cm）便于瞄准，不会拖坏纸面。
- 按 **D11** 或发送 `SET` 记录当前点：用**正解**把当前关节角换算成精确的 `(u, v)` 存入 `teachU[] / teachV[]`，并回显"已记录示教点 n/5"。记录的是实际到达的位置，因此后续复现一定能到达。
- 5 个点记录完毕后可用 `CLR` 清空重录，`DRAW` / `CURVE` 开始自动绘制。

> 现场答辩时考官临时指定五个点，只需 `TEACH` → 摇杆找点 → `SET` ×5 → `DRAW`/`CURVE`，
> **不需要重新编译或烧录**，符合考核要求。

**（2）自动绘制流程**

严格按"先返回待机位置，再移动至第一个目标点，之后依次连接"的要求：

```
回待机位 (0, 8, h=4)  →  抬笔移动到点 1 正上方  →  落笔到点 1
  →  点 1 → 点 2  →  点 2 → 点 3  →  点 3 → 点 4  →  点 4 → 点 5
  →  抬笔回到待机位
```

每段用 25 个插值点细分（`t` 从 1/25 到 1），保证**实际走出来的轨迹是直线**而不是"两点之间直接甩过去"。
绘制全程受 5.4 的暂停 / 继续 / 取消控制。

`DEMO` 指令用内置的五个点快速演示，方便调试和录制视频。

### 5.6 子任务 5：五点示教 + 平滑曲线轨迹规划（难度 30）

**代码模块**：`drawByTeach(true)` / `catmullRom()`

示教与记录方式与子任务 4 完全相同，区别在轨迹生成：使用 **Catmull-Rom 样条**。

**为什么用 Catmull-Rom**：两点连直线在折点处方向突变，机械臂走到折点相当于"急转弯"，既难看又容易抖动。
Catmull-Rom 的好处是**曲线严格经过每一个给定的点**（不像 B 样条只逼近），这对"示教点必须过点有效"的评分要求是刚需。

**原理**：画第 `i` 段（连接 `P[i] → P[i+1]`）时，不只用自己的两个端点，还"偷看"前后邻居 `P[i-1]` 和 `P[i+2]`，用这四个点决定这一小段的走向：

```
u(t) = 0.5 × ( 2·P1
             + (−P0 + P2)·t
             + (2·P0 − 5·P1 + 4·P2 − P3)·t²
             + (−P0 + 3·P1 − 3·P2 + P3)·t³ )
```

- 起点处切线方向 = `P2 − P0`，终点处切线方向 = `P3 − P1`；
- 相邻两段共享同一个算法，段与段之间切线连续变化 → 整条曲线处处平滑（数学上称 **C1 连续**）；
- **端点处理**：第一段缺 `P[-1]`、最后一段缺 `P[n]`，直接"复制"端点（`P[-1] = P[0]`，`P[n] = P[n-1]`），曲线从第一个点平滑滑入、平滑滑出；
- **过点验证**：代入 `t=0` 得 `u = P1`，代入 `t=1` 各项合并后得 `u = P2`，因此每个给定点都是曲线上的点——**这是数学保证，不是近似**。

每段采样 30 个点。自动绘制流程与子任务 4 一致（回待机 → 抬笔到点 1 → 落笔 → 沿曲线过五点 → 抬笔回待机），同样支持暂停 / 继续 / 取消。

> 当前状态：轨迹生成代码已完成，但受机械精度和笔尖固定方式影响，实测曲线效果未达到要求，本项按半完成计算。

### 5.7 速度控制

速度由**全局速度档**统一控制，`H` / `L` 指令或串口调整：

```
每步延时 STEP_DELAY_TAB[5]  (ms)            档 1~5 → 100 / 50 / 28 / 16 / 9 ms
```

之所以用"每步 1° + 延时"而不是直接 `write(目标角)`：舵机一旦收到差距很大的目标角会全速冲过去，速度不可控、启停冲击大。
**拆成 1° 的小步 + 固定延时**，等价于给舵机制造了一个软件速度环，动作平稳可控，也才可能实现"暂停后原地停住、继续后接续"。

另外插值点数（直线 40 点、图形每边 25 点、折线每段 25 点、曲线每段 30 点）也影响绘制速度与平滑度，
点数越密越平滑但越慢，可在代码顶部的参数区调整。

## 六、异常处理与鲁棒性

| 异常情况 | 处理方法 | 位置 |
|---|---|---|
| 目标点超出机械臂可达范围 | 沿原方向**钳制到可达球面**（`d` 缩放到 `L1+L2` 的 99.5%），机械臂朝目标方向走到极限并打印 `WARN`，**而不是原地不动或乱走** | `tableToJoints()` |
| 逆解失败导致使用未初始化变量 | 早期版本不可达时直接 `return`，调用方会拿到栈垃圾、机械臂乱甩。现已改为**返回 `bool` + 输出参数赋哨兵值**，调用方检查返回值后跳过该点 | `kinematics.ino` `tableToJoints()` |
| 目标关节角超出实测行程 | 逆解算出的舵机角统一钳到 `SH_MIN/MAX`、`EL_MIN/MAX` 等实测范围内；**所有**舵机输出在 `writeServos()` 处再钳一次 | `kinematics.ino` `writeServos()` |
| 目标半径/底座角超出可达范围 | `r` 钳制到 `[R_MIN, R_MAX]`，底座角钳制在 `BASE_ANG ± BASE_SWEEP` | `tableToJoints()` |
| 示教点不足 | `DRAW` / `CURVE` 前检查 `teachCount ≥ 2`，否则提示"示教点不足 2 个"并拒绝执行 | `drawByTeach()` |
| 示教点超过 5 个 | 拒绝记录并提示"如需重录请发送 CLR 清空"，不会数组越界 | `recordTeachPoint()` |
| 回放时还没有录制数据 | 提示"还没有录制数据，请先按 2 录制"并拒绝执行 | `playRecord()` |
| 录制时长不足 10 秒 | 结束录制时打印 `WARN 录制时长不足 10 秒，建议重新录制` | `toggleRecord()` |
| 录制缓冲写满 | **自动结束录制并保留已录数据**（不丢帧），打印提示 | `recordStep()` |
| 串口缓存溢出 | 单条指令超过 48 字节时丢弃并提示 `ERR: 指令过长`，不会越界 | `pollOne()` |
| 串口收不到换行符 | 字符间隔超过 40ms 自动分帧，兼容不带换行的遥控板 | `pollOne()` |
| 动作执行中途收到新指令 | 只受理 `PAUSE` / `RESUME` / `CANCEL` / `STATUS`，其余回 `BUSY`，避免递归触发动作导致状态错乱 | `dispatchInMotion()` |
| 按键抖动 / 连击 | 180ms 时间锁消抖，一次按下只触发一次 | `scanButtons()` |
| 上电瞬间舵机乱甩 | `setup()` 里先统一写 90° 中间安全姿态 | `setup()` |
| 取消绘图后标志未清除 | `endDrawTask()` 先清 `stAbort` 再回待机位，否则回程本身也会被立刻取消 | `endDrawTask()` |
| 内存不足 | 不使用 `String`（避免碎片），串口用固定 `char[]` 缓冲，录制用 `uint8_t` 压缩存储；实测 Flash 14.1KB/32KB、静态 SRAM 1.0KB/2KB | 全局 |
| 函数名与标准库冲突 | 状态上报函数由 `stat()` 改名为 `printStat()`，避免与 POSIX `stat()` 撞名 | `printStat()` |

## 七、标定步骤（画图前必做）

程序里的几何参数必须按实物标定，否则画出来是歪的：

1. **量尺寸**：`ARM_L1`（肩轴 → 肘轴）、`ARM_L2`（肘轴 → **腕轴**，注意：**不是笔尖**）、
   `L3A`（底座转轴 → 肩轴，水平）、`L3B`（腕轴 → 笔尖，水平）、
   `PEN_DROP`（腕轴 → 笔尖，竖直）、`H_SHOULDER`（肩轴离**纸面**的高度）。
   注意：`H_SHOULDER` 要从**纸面**量（不是桌面、更不是底座轴）——
   竖直零点在纸面上，底座转轴自身的高度不进公式。
2. **定零点（`TRIM`）**：注意：**2026-10-13 晚改了方法** ——
   老的「用摇杆把大臂抬到**水平前伸**再看 `CAL`」现在**做不到了**：
   `SHOULDER_TRIM = 175` 已**超出舵机实测上限 170**，`a1` 最小只到 **8.4°**。
   改成 **量高度、拟合**：
   - 发几个 `S`（如 `S130` / `S145` / `S160`），每点量【**肘轴轴心**】离纸面的高度
     ⇒ 用 `h = H_SHOULDER + ARM_L1·sin(TRIM − S)` 反解 `SHOULDER_TRIM`；
   - **大臂固定不动**，发几个 `E`（如 `E70` / `E90` / `E110`），每点量【**腕轴轴心**】离纸面的高度
     ⇒ 用 `h_腕 = h_肘 + ARM_L2·sin(E − ELBOW_TRIM)` 反解 `ELBOW_TRIM`。
   - 把实测数据代入上面的公式重新计算即可。
   - 方向反了 → 翻开对应的 `SHOULDER_INVERT` / `ELBOW_INVERT` / `BASE_INVERT`。
     注意：**高度数据分不出 `SHOULDER_INVERT`**（`sin` 是对称的）—— 要另外看
     「`S` 开到最大时肘轴在底座的**前方**还是**后方**」（`cos` 的正负，两边差 16cm）。
   - 也可以直接用 `JOG 大臂角 肘角` 逐度试（0 = 水平前伸）。
     注意：**小臂那个角现在是【小臂绝对角】**：0 = 小臂**水平**，不是"相对大臂的折角"。
     `JOG 0 0` = 大小臂都水平 = 共线 = 机械止点够不到，**别发**。
3. **验"绝对角"成立**：大臂固定在某个位置（如发 `S130`）不动，只扫小臂 `E`，
   每个点量【肘轴】和【腕轴】两个高度，**相减**得到"小臂相对肘轴抬了多少"。
   注意：**必须再换一个大臂位置重做一遍。** 只在一个大臂位置上量，
   分不出"小臂角是绝对角还是相对角"—— 两种写法在同一个大臂角下是同一个式子（见 5.1 节的注）。
4. **校落点**：把笔尖手动移到桌面某个已知位置，执行 `CAL` 读出程序认为的 `(u, v)`，
   与卷尺量的实际值对比。
   注意：想验笔尖**高度**准不准，最好的判据是：发一个 `h = 0` 的目标，
   看笔尖是**触到纸**还是**浮在纸上** —— 这个判据**不靠尺子**，没有读数误差。
   注意：`L3B` 不好用尺子直接量，用**画弧法**：笔尖压在纸上、**只转底座**扫出一整条弧，
   量**弦长 `c`** 与**矢高 `s`** ⇒ `R = s/2 + c²/(8s)`（**不用知道转了多少度**）
   ⇒ `L3A + L3B = R − L1·cos(a1) − L2·cos(a2)`。
   想让结果准，弧要**尽量扫大**（`s` 越大，量尺误差的放大倍数越小），
   而且**纸必须四角贴死在桌上**（否则笔压着纸推，弧会变形、算出的 `R` 偏大）。
