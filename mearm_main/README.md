# mearm_main —— meArm 控制主程序（提交用）

任务一 / 二 / 三 / 五 全部功能的**整合工程**，一份可直接编译、烧录、复现视频效果的代码。

> 按任务拆成六个文件，但仍然是**一份工程**：Arduino 编译一个 sketch 目录时，会把
> 目录下所有 `.ino` 自动合并成一个编译单元，顺序为「主文件（与目录同名）在最前，
> 其余按字母序」。因此不需要任何额外配置，打开 `mearm_main.ino` 就能整体编译。
>
> 烧录：Arduino IDE 打开 `mearm_main.ino` → 选板子 Arduino Uno → 上传。

## 文件分工

| 文件 | 内容 |
|---|---|
| `mearm_main.ino` | 公共常量与全局状态、`setup()`/`loop()`、串口接收与分帧、指令派发、`HELP` |
| `kinematics.ino` | 按键扫描、`writeServos()` 安全限位、运动基元、正逆解、`CAL`/`JOG` 标定工具 |
| `task1_basic.ino` | 任务一：摇杆操控、`O`/`S`/`H`/`L`、`x,y,z` 协同 |
| `task2_pick_place.ino` | 任务二：A / B / C 取放点位与六步取放路径 |
| `task3_keyboard.ino` | 任务三：按键1 循环夹取、按键2 录制、按键3 回放、按键4 回中 |
| `task5_drawing.ino` | 任务五：绘图引擎、五点示教、折线与 Catmull-Rom 平滑曲线 |

> ⚠ 拼接顺序带来的约束：**跨文件使用的全局变量必须定义在 `mearm_main.ino`**（它排在最前）。
> 各任务专属的状态变量都放在各自文件里；跨文件的函数原型只允许出现内建类型
> ——Arduino 会把自动生成的函数原型插到合并文件开头，原型里一旦出现自定义结构体，
> 就可能落在结构体定义之前导致编译失败。

```cpp
const float ARM_L2 = 8.0;        // 小臂长度 cm：肘轴 → **腕轴**（不是笔尖！）

const bool SHOULDER_INVERT = true;
const int  ELBOW_TRIM = 101;     // ★小臂【绝对角】= 0（小臂水平）时的舵机角（2026-10-13 晚 100 → 101）
const bool ELBOW_INVERT = false;
const bool BASE_INVERT = true;
const int  ELBOW_SIGN = -1;      // 肘部解支，桌面画图用 -1
```

**上面这些数 2026-10-13 晚全量重标过**（机械臂 + 夹爪都又微调）：
行程 `B 8~172 / S 38~167 / E 28~127 / G 60~127(逻辑)`、`BASE_ANG = 86`、
夹爪 张开 127 / 空爪 60 / 夹笔 70、`R_MIN/R_MAX = 8.5/24.5`。
完整过程和数据见 `断点_2026-10-13.md`、`夹爪档案.md`。

> ★ **2026-10-13 晚 两个方法级变化：**
> - **零点改成"量高度拟合"** —— `SHOULDER_TRIM = 175` 已**超出舵机上限 170**
>   ⇒「大臂水平」**物理上摆不到**，`a1` 最小只到 8.4°。老办法（摆三轴等高）作废。
>   脚本 `tools/fit_trim.py`。
> - ⚠ **`L3B` 还没定死**（暂沿用 7.8）：画弧法两轮给 20.15 / 21.20，模型 19.81，
>   精度不够分不出来 ⇒ 要扫 ±55° 大弧重测。定稿后 `R_MIN/R_MAX` 要跟着平移。
> - ⚠ 高度数据**分不出** `SHOULDER_INVERT`（`sin` 对称）—— 靠"`S167` 时肘轴在底座**前方**"定的 `true`。

> ★★ **2026-10-10 晚有一处模型级更正**：小臂角是**绝对角**，不是相对角。
> 正解里是 `a2 = ce`（不是 `cs + ce`），逆解里发给小臂舵机的是 `a2 = s + e`，
> `ELBOW_TRIM` 的含义也因此变成"小臂**水平**时的舵机角"。
> 理由、实测数据、连带影响见 `docs/任务四_补充_平行四边形与末端偏移.md` 第 0 章。
> ⚠ 连带新增了 `ELBOW_OVER_ARM_MAX`（小臂不得高过大臂）的保护 ——
> 改成绝对角后这条不再自动成立，不钳制会顶到机械止点。

## 舵机安全行程（实测，2026-10-09）

`kinematics.ino` 顶部的 `BASE_MIN/MAX`、`SH_MIN/MAX`、`EL_MIN/MAX`、`GR_MIN/MAX`
由 `tools/mearm_range_test/` 逐度扫描实测得到（各留 3° 余量），**所有舵机输出统一在
`writeServos()` 里被钳制到这些范围内**，任何指令、逆解、摇杆都不可能把关节顶到
机械止点上憋劲。拆装舵机臂后必须重新实测并更新。

> ⚠ **夹爪数字的口径是「逻辑角：大 = 张开」**，和舵机原始角正好相反。
> 硬件本身是小角开、大角闭（实测原始角 50 = 开 / 170 = 闭），代码在
> `writeServos()` 这个唯一出口做了一次镜像：`原始角 = 220 − 逻辑角`。
> 全程序其余地方（`GRIP_OPEN`/`GRIP_CLOSE`、`GRIP_CLOSE_OBJ`、`PEN_GRIP`、
> `F<角度>`、`G<0~100>`）一律用**逻辑角**。
> 和 `tools/mearm_range_test/` 的读数对照时换算一次：**逻辑角 = 220 − 工具读数**。
>
> ⚠ 夹爪的下限 `GR_MIN`（现 66）不是 range test 那个"止点"，而是**两爪刚好夹上、不顶**
> 的位置 —— 再往紧一点就是硬碰硬堵转（烧过一次舵机）。所以它与 `GRIP_CLOSE` 取同一个值。

标定流程见 `docs/说明文档.md` 第七节。用 `JOG 0 0` 和 `CAL` 两个指令可以快速校准。

## 资源占用（实测）

Flash 14.1 KB / 32 KB，静态 SRAM 1.0 KB / 2 KB —— Uno 上余量充足。
录制缓冲已按 SRAM 限制压缩为 `uint8_t[200][4]`（12 秒），不要盲目调大 `REC_MAX`。
